# app 目录约定

`app/` 根目录只保留包声明和本说明文件。可执行入口统一位于 `entrypoints/`，历史裸模块适配器统一位于 `compat/`，实际实现按领域存放：

| 领域目录 | 实现内容 |
|---|---|
| `automation/` | Cron 规则与调度服务 |
| `backtesting/` | 独立的多源历史日 K、服务端持久任务、选股信号与策略买卖回放；不被模拟交易加载 |
| `compat/` | 历史裸模块名适配器，不承载业务实现 |
| `core/` | 路径、缓存等基础设施 |
| `dashboard/` | Dashboard 服务、公开投影、版本化快照、API、安全辅助、行情采样与页面侧任务编排 |
| `entrypoints/` | Dashboard、调度器、监控与报告等可执行入口 |
| `market_data/` | 行情访问、证券代码规范化、日 K/量能缓存与问财研究数据客户端 |
| `messaging/` | 通知模型、渠道、分发与兼容层 |
| `monitoring/x/` | X 监控服务、解析、格式化与状态规则 |
| `reports/a_share/` | A 股竞价、午盘、盘后、日历与 Grok 报告 |
| `reports/us/` | 美股盘面和机构评级报告 |
| `screening/` | 多策略/全市场扫描、候选增强与题材强度缓存 |
| `storage/` | 推送历史、模拟盘数据库、迁移与报告存储 |
| `strategies/` | 策略注册、评分、归因、风险预算、Prompt 与退出规则 |
| `trading/` | 模拟账户、模型决策、执行风控、优化器和卖出信号 |

`backtesting/` 的历史 K 线按东方财富、腾讯、新浪顺序降级；新浪仅支持不复权模式，前/后
复权回测因此只使用东方财富和腾讯。牛牛题材优先使用东方财富 `f103` 多概念归属，板块潮汐
优先使用东方财富 `f100` 行业；分类批量响应会原子保存为私有日快照。刷新失败时优先复用已
校验的东方财富旧快照。仅在完全没有有效东方财富快照时，已启用且配置密钥的问财数据源才可
使用完整分页并校验过的同花顺行业/概念快照冷启动；两套分类口径独立缓存且不混合补洞。两者
均不可用时，回测明确失败。
Dashboard 的“今日前5”另读取东方财富概念板块涨幅榜前 100，按规范化后的精确题材名展示即时
排名、上涨广度和领涨股，仅用于交叉验证。该快照采用分钟级进程缓存、短时陈旧回退和失败退避；
它不参与牛牛题材归因、今日强度排序、跨日确认、回测或交易门槛，接口失败时原排名照常生成。
分钟题材重算及大型缓存序列化通过 `entrypoints/niuone_minute_refresh.py` 在有界隔离进程执行，
Dashboard 主进程继续提供上一份有效读模型；行情快照在等待期内只保留最新一份，并按耗时自适应降载。
完整选股、独立题材研究或日 K 预热运行时，分钟重算自动让行并在任务结束后消费最新快照，避免重型任务叠加。
管理员回测由单任务、低优先级独立子进程执行，结束后由操作系统回收行情与题材截面内存；
Dashboard 只负责持久化状态和结果。选股回放带按协议、日期、行情源、复权方式、股票池、
分类快照及实际历史行情指纹缓存，执行参数变化可复用选股结果；缓存损坏或写入失败时自动重算。
牛牛多概念股票按试仓、启动、领涨、转强各自选择生命周期相容的题材画像；主/次主线是排序展示字段，不是只允许两个题材交易的资格门槛。回测拒绝诊断按自然月保留评分阈值敏感性、硬门槛逐项/分族消融和龙头分支覆盖。

牛牛严格前向证据沿用模拟账户真实成交链路：Cron Scheduler 启动时及工作日首轮决策前先冻结或校验协议，完整成交 payload 与每轮完整观察候选/过滤结果幂等持久化在私有 SQLite。成交、决策、日内权益和日度权益历史先以不可变版本追加到 SQLite，归档事务成功后账户 JSON 才有界保留当前状态和近期记录；盘后评估器只读重建零仓到零仓生命周期。Scheduler 与 Dashboard 分别有界保留每日任务结果和每个 Practice 决策槽的终态；协议 v20 还逐槽核对耐久决策账本，并按五阶段输出“观察候选→进入决策池→模型 BUY→实际 BUY”的去重决策周期漏斗及定仓利用率。牛牛新仓按北京时间交易日从耐久成交状态跨决策轮次累计，每日最多 2 只，加仓和其他策略不占该额度。空候选池是有效观察；延迟成交继承原槽机会集，字段残缺或内部矛盾的证据不能满足槽账本。只有预检早于首槽、全部配置槽都完成扫描与决策且落盘、两次独立退出检查、15:15 盘后账户净值快照和 15:20 评估均成功的 A 股运行日才算完整。首次入场会同时冻结按题材前态因果推进的主线五阶段代码、中文标签、顺序、入口策略和行业；持仓期间每次主线扫描继续记录紧凑阶段路径，真实 SELL 再冻结退出阶段。报告按入口阶段、退出阶段、完整路径和行业分组，并要求每个实际运行日都有阶段观察。队列起始日前允许同一起始日的预锁保留旧指纹审计后自动重冻，起始日当天及以后仍禁止覆盖漂移锁。只有全部已完成生命周期都具备完整入口与持仓路径归因、且队列内运行覆盖率为 100% 时，交易数/时间门才可进入人工复核；旧账本、阶段错配、状态层独有成交或运行日缺口都不能推动策略晋级。
协议同时冻结五阶段与四动作的唯一入口路由：酝酿→试仓，主升→启动/领涨，高潮→满足条件的领涨或企稳转强，分歧→仍有效的领涨或企稳收复后的转强，退幕→只退出。牛牛不设固定单日涨幅上限，成交前仅拒绝实际执行价已经达到涨停的买单；评分、决策候选、成交前复核、历史回放和盘后证据门共用该路由，其他阶段、形态与风险错配仍不能进入可交易池。
v20 漏斗中的“实际 BUY”来自耐久成交账本，并与决策 payload 的执行副本交叉核对，不以单一副本替代真实成交证据；存在结构缺口或交叉账本不一致时同样保持 `data_quality_blocked`。协议锁还冻结起始日前的零持仓账户基线、每日牛牛新仓数值与计数口径；队列内只要出现非牛牛/未知策略成交，任一实际运行日缺少持仓阶段观察或耐久盘后权益点，组合收益与回撤证据就失败关闭。满三个月但不足 30 笔只开放频率/运营复核；成效声明还须同时通过冻结历史胜率参考、交易级 Wilson 95% 下界、按首次入场日期×行业计算的唯一簇数和 Herfindahl 有效簇数、簇等权胜率及其 95% 下界、费用后生命周期收益、正组合收益、最大回撤不超过 6%、收益/回撤不低于 1，以及运行日与机会漏斗完整性，且绝不自动晋级。

v18 同时冻结牛牛 BUY 与模型 SELL 的安全裁单语义：BUY 若已通过资格、容量和风险输入检查，只是 100 股整手请求高于正数确定性风险上限，则按上限成交；模型 SELL 若请求高于正数整手 T+1 可卖量，则按可卖量成交。SELL 的模型请求、当时可卖量、实际股数和裁单标记进入耐久成交并由盘后质量门校验；需要裁单但可卖量为零或非整手时仍拒单，系统自动退出与其他战法维持原执行语义。
v18 还冻结牛牛试仓日线 V 型恢复比 `[0.60, 2.00)`：不足六成视为右侧确认不完整，达到两倍则已超出早期试仓语义；评分和成交前复核共用同一失败关闭规则。冻结历史参考胜率同步更新为 59.29%，仍须由未见前向样本证明，不自动宣称未来改善。
v18 同时冻结主升质量边界：牛牛领涨必须处于主线内前 20% 且题材当日强度不低于 60；牛牛启动只允许跨日延续的 `emerging`，已确认 `mainline` 必须改走领涨。三项规则在评分和成交前都失败关闭。
v18 进一步冻结酝酿试仓的延续质量与资金边界：题材强势股数必须不少于 6，或酝酿状态至少连续 3 个交易日；每天最多保留 2 个合格试仓，单票绝对仓位上限为 6.25%。评分与成交前复核共用延续 blocker，进攻/轮动/修复的单笔风险预算仍为 0.35%/0.30%/0.25%。
v20 将阶段化资金路由拆成两级：6.25% 只约束酝酿试仓；原试仓或启动仓浮盈处于 2%～12%、仍处主升且仍为强势领涨时，启动主线跨日延续先在下一交易时段向 10% 上限加仓一次，主线完全确认后再向 20% 上限加仓一次。实际目标始终取风险定仓、主题/组合容量、现金和阶段上限的最小值；浮盈超过 12% 不追仓，高潮、分歧、退幕不加仓。首次进入高潮且持仓不亏时减仓 1/3 一次，原分段止盈、成本保护与 2ATR 跟踪保持。

v21 把确认领涨后的仓位管理改为可重复的波段再平衡，而不是再增加一个固定加仓次数：距本轮收盘高点回落 1 ATR，或至少连续 3 个交易日未创新高且回落不少于 0.25 ATR 时，先减仓 1/3；随后只有价格从减仓价重新上行 0.5 ATR、生命周期回到主升且个股恢复强势领涨，才补回风险预算允许的目标仓位。每次补仓都会重置周期，必须等待下一次独立回撤才可再次减仓/加仓，因此终身次数不设上限；高潮、未修复分歧和退幕仍禁止加仓。严格前向协议同步升级为 `niuone-strict-forward-v21`。
v22 修复多概念动作路由和分歧领涨阶段错配：四个动作各自选择相容题材画像，页面主/次主题不再限制其他已确认分支，`diverging` 强势核心领涨不再被 `mainline` 状态和题材当日强度 60 的矛盾门槛二次阻断。组合容量、价格形态和结构风控保持；严格前向协议升级为 `niuone-strict-forward-v22`，默认新队列从 `2026-08-04` 开始。
v23 为已进入主升、仍处 `emerging` 且完成跨日延续的行业龙一增加“主升动量试仓”子路由：仅接受强度不低于 90、评分不低于 8.0、非防守行情且次日执行高开不超过 3% 的候选。该路由可容纳不超过 3.2ATR、18%/3ATR 的价格与结构空间，但首仓绝对上限固定为 3%，并继续按有效亏损距离缩仓；普通启动、反转与领涨门槛不变。严格前向协议升级为 `niuone-strict-forward-v23`。
v24 收紧主升动量试仓的中间追高区：普通路径要求评分不低于 8.1、题材分不低于 70 且距 EMA20 不超过 1ATR；2.5～3.2ATR 只保留单日涨幅不低于 9.5%、量比不高于 1.2 的极强加速例外，继续覆盖 600206 型龙头。高质量试仓绝对上限由 3% 调整为 4%，实际仓位仍受有效亏损距离风险预算约束。严格前向协议升级为 `niuone-strict-forward-v24`。
管理员回测 v25 固定使用进取风险参数，不再对外提供均衡/进取选择；旧客户端即使传入 `balanced` 也会被强制归一化为 `aggressive`。回测协议升级为 `niuone-backtest-v25`，旧协议或旧均衡结果不再恢复；分支报告继续把“最佳标的当日阻断”与“月度累计阻断族”分开。进取参数仅放大回测账户风险、仓位敞口和持仓容量，不改变子路由身份条件或实盘/Practice 组合风控。
v25 为已经完成高潮减仓、个股仍强且题材分不低于 55、未进入退幕的领涨余仓增加条件化主升跟随：相对龙头排名退出由连续 2 日改为 3 日确认，ATR 跟踪线由 2ATR 放宽至 3ATR。未减仓仓位、弱势个股和衰退题材仍沿用原两日/2ATR 风控，结构止损、成本保护、主线转弱和市场硬停止不放宽。严格前向协议升级为 `niuone-strict-forward-v25`；管理员回测同步升级为 `niuone-backtest-v26`。
v26 将防守状态从“零预算禁开仓”改为牛牛最低风险档：成熟路径单笔/组合/主题风险上限为 0.30%/0.90%/0.60%，总仓/主题敞口为 20%/12%；试仓进一步收紧为 0.15% 单笔风险、0.30% 主题风险和 5% 主题敞口。防守状态可开仓，复合风险硬停止仍只允许卖出或持有。严格前向协议升级为 `niuone-strict-forward-v26`，管理员回测同步升级为 `niuone-backtest-v27`。
v27 将股票的东方财富 `f100` 事实行业与牛牛动作选中的 `f103` 题材拆开保存：候选的 `industry/sector` 只表示行业，`signal_theme` 表示本轮入选题材。多概念归因由 75% 当前题材/个股共振证据和 25% 前序快照历史先验组成，所有概念权重归一化为 1；首次建仓冻结 `entry_theme` 及归因依据，持仓只有在另一有效生命周期题材连续 2 个交易日领先至少 10 分后才切换 `active_theme`。题材容量和风险按动作/有效题材计算，页面同时显示题材与行业。严格前向协议升级为 `niuone-strict-forward-v27`，按首次入场日期×入场题材聚类并要求完整题材归因；管理员回测同步升级为 `niuone-backtest-v28`，旧协议证据不得混算。
v29 将 `f103` 明确降级为题材候选集：个股只按排除自身后的同题材共振、同群方向、当日排名和结构排名形成当前归因证据，再叠加前序先验；题材识别不发起消息面检索，消息摘要不会新增候选、修改归因分或改变题材总分。多概念使用 softmax 分配并保留未归因质量，避免弱标签被强制分满。题材强股、成交额、广度和领涨股随后按归因权重重算，今日广度按有效归因样本向全市场广度收缩；低于 15% 归因权重的股票不得成为该题材领涨股，Dashboard 折叠由同一核心群驱动的标签副本。独立题材页扫描直接跳过消息预检；普通策略扫描仍可将消息面用于候选股买入前风险检查，但不参与题材识别。题材上下文升级为 v10，旧 v9 上下文不参与跨日确认；严格前向与管理员回测协议分别升级为 `niuone-strict-forward-v29` 和 `niuone-backtest-v30`，部署前须归档旧锁、报告和回测结果。
v30 在候选标签之间加入 20 个交易日的市场中性化收益波形归因：先从个股和同题材其他成员的日收益中扣除全市场中位收益，再计算排除自身后的题材中位波形相关性，并按同一股票全部 `f103` 候选中的相对排名收缩。这样可抑制“5/20 日方向相同但逐日波形无关”的宽泛标签。牛牛的完整研究、分钟刷新和普通策略扫描均不发起消息检索或大模型调用；题材上下文升级为 v11，专用缓存升级为 v9，严格前向与管理员回测协议分别升级为 `niuone-strict-forward-v30` 和 `niuone-backtest-v31`。
v31 修复多概念龙头被 softmax 份额重复惩罚的问题：归因权重继续用于题材广度、成交额、集中度和普通分支过滤，但每只股票归因分最高且不低于 60 的首要题材，即使因候选标签较多而份额低于 15%，仍可参与该题材的龙头资格。资格确定后，结构龙头按个股原始强度、今日龙头按当日涨幅排序，归因分仅作同值次序，不再使用“强度/涨幅 × 归因权重”二次稀释。回测以真实次日开盘校验结构止损资格，5bp 模拟滑点只进入成交价和风险定仓，避免把边界内开盘误判为超限。生命周期、买点、结构止损、涨停和组合风险门槛不变；题材上下文/专用缓存升级为 v12/v10，严格前向/管理员回测协议升级为 `niuone-strict-forward-v31`/`niuone-backtest-v32`。
协议指纹还覆盖预检/盘后 Cron、耐久成交数据库与恢复状态的有效路径，以及调度、存储和评估源码；这些值只保存 SHA-256。`--as-of` 只控制报告截点，协议锁的冻结/重冻资格始终使用实际墙钟日期，不能用回填日期跨过队列起始日改写原锁。

`entrypoints/` 中的脚本是项目支持的启动路径。`compat/` 通过 `_compat.py` 在历史模块命名空间中运行迁移后的实现，供内部裸模块导入和迁移期集成使用。新增业务代码不得写入 `entrypoints/` 或 `compat/`。

Dashboard 继续由 `entrypoints/niuone_dashboard.py` 单端口启动并保留原页面布局。`dashboard/fastapi_app.py` 只负责 FastAPI/Uvicorn 应用组合、中间件、Vue 构建和共享缓存响应，具体 HTTP 接口按 system、messages、market、practice、admin 拆在 `dashboard/routers/`。旧 `BaseHTTPRequestHandler`、`ThreadingHTTPServer` 及原生 HTML/JavaScript 控制器已经删除。`dashboard/security.py`、`dashboard/visit_stats.py` 和 `dashboard/response_cache.py` 分别承载管理员访问控制、访问统计和并发响应缓存，`dashboard/server.py` 保留后台状态、配置、数据源、行情采样和实战计划的组合实现，但不再定义 HTTP 路由。浏览器展示模型由 `dashboard/public_projection.py` 构建，并由 `dashboard/public_snapshots.py` 原子发布；交易和外部请求不得下沉到前端。

高频投影只读取 `practice_candidates_latest.json` 与 `niuone_mainline_summary_latest.json` 两个有界快照，并按文件身份、大小和纳秒修改时间复用已解析对象。完整候选扫描与逐股题材归因仍保留在原私有缓存中供交易和跨日确认使用；升级后若小型快照尚不存在，Dashboard 只兼容读取一次旧缓存并原子补建，不删除或覆盖完整研究数据。
