# app 模块结构

`app/` 根目录不再放业务实现或零散入口。受支持的命令行/服务入口集中在 `app/entrypoints/`，历史裸模块适配器集中在 `app/compat/`，其余子包承载领域实现。兼容适配器由 `_compat.py` 在历史模块命名空间中执行迁移后的实现，因此运行时 monkeypatch 语义保持不变。

## 领域边界

| 目录 | 职责 | 不应承担的职责 |
|---|---|---|
| `app/core/` | 运行路径策略、原子 JSON 缓存等跨领域基础设施 | 业务规则、服务编排 |
| `app/automation/` | 定时任务模型、Cron 匹配、子进程执行、失败重试和调度器状态 | 报告正文生成、策略评分、成交实现 |
| `app/backtesting/` | 独立的多源历史日 K、逐日选股、固定周期收益与策略买卖回放 | 模拟账户、真实持仓、订单执行、生产调度 |
| `app/dashboard/` | FastAPI 路由、安全辅助、公开展示投影、版本化快照、API 缓存、行情采样及页面侧实战计划编排 | 策略评分细节、账户存储实现、外部数据源解析 |
| `app/market_data/` | 行情/研究数据访问、证券代码规范化、日 K 与量能缓存 | 策略决策、账户与成交状态 |
| `app/messaging/` | 通知模型、渠道适配、HTTP 传输、分发和成交消息格式 | 交易状态持久化 |
| `app/monitoring/x/` | X 关注列表抓取、媒体/上下文解析、消息格式、进程循环与重试状态 | Dashboard 路由、交易决策 |
| `app/reports/a_share/` | A 股竞价、午盘、盘后、日历、龙虎榜和模型增强报告 | Cron 触发时机、Dashboard 路由 |
| `app/reports/us/` | 隔夜美股摘要与机构评级报告 | Cron 触发时机、Dashboard 路由 |
| `app/storage/` | 消息历史、模拟盘、报告的 SQLite/文件存储接口、去重与迁移 | 策略评分、HTTP 路由 |
| `app/screening/` | 多策略/全市场扫描、候选行业增强、题材强度与分钟缓存编排 | 账户执行、HTTP 路由 |
| `app/strategies/` | 策略注册、评分、归因、选股、风险预算、退出规则和提示词片段 | 行情 I/O、账户落盘 |
| `app/trading/` | 模拟账户、模型决策、执行风控、成交落盘、优化器和卖出信号 | Dashboard HTTP 路由、Cron 调度 |

`entrypoints/` 中的 Dashboard、交易器、调度器、监控器和报告入口均为薄启动器；`compat/` 中的各 `*_dashboard_api.py`、`notifications.py` 及历史模块名均为薄适配器。Dashboard 的生产 HTTP 组合层位于 `dashboard/fastapi_app.py`，接口实现按领域位于 `dashboard/routers/`；`dashboard/server.py` 保留后台状态、配置、数据源、行情采样和页面侧实战计划的组合函数。其他实际组合实现位于 `trading/practice_trader.py`、`automation/scheduler_service.py`、各领域的 `*_service.py` 等文件。

组合层的正式执行合同是直接运行 `app/entrypoints/*.py`。领域实现使用 `app.<domain>` 包路径；仍依赖历史裸模块名的组合代码由入口统一加载 `app/compat/`，外部代码不应再依赖已经移除的 `app/*.py` 路径。

## 依赖方向

```text
启动脚本 / 兼容入口
        ↓
服务与组合层（dashboard、automation、screening、trading、reports、monitoring）
        ↓
规则与基础层（strategies、market_data、messaging、storage、core）
        ↓
标准库与外部数据源
```

`backtesting/` 是按需运行的离线研究模块，只读复用 `strategies.scoring`。生产扫描和模拟交易不得反向导入它；Dashboard 仅允许通过受保护的回测 API 适配器创建和查询研究任务。回测候选范围来自当前 A 股列表接口，历史日 K 每次按本次完整日期窗口从外部行情源获取，不读写本地日 K 缓存。自动多源模式对确定性数据失败不做无效重试，并在单次任务内按共享健康样本熔断大面积失效的优先源；显式选择单一行情源时不启用跨源熔断。

严格前向评估属于 `trading/` 的派生链路，而不是 `backtesting/`：Cron Scheduler 每次启动立即执行无数据库依赖的协议预检，工作日 09:05 再复检，从而在 09:25 首轮计划决策前冻结评估口径、牛牛评分/选择/退出/执行相关源码、非密钥运行配置的 SHA-256 指纹，以及不含股票代码的零持仓账户基线。模拟账户随后把含首次入场上下文和仓位边界的完整成交 payload，以及每轮完整观察候选、入选状态和过滤原因，幂等写入私有 `niuniu.db`；牛牛执行层按北京时间交易日从成交状态跨轮累计首次建仓代码，每日最多 2 只，加仓和其他策略不占额度。评估服务再以耐久历史为主、最近 JSON 为非耐久恢复覆盖，按零仓到零仓重建实际生命周期。Scheduler 有界保存预检、开盘/尾盘退出、15:15 无交易盘后净值快照与 15:20 评估结果，Dashboard 有界保存每个配置 Practice 槽的扫描和决策终态；协议 v18 要求队列内每个实际 A 股运行日的预检早于首槽、全部槽均为 `ok`、每个槽都有完整 SQLite 决策证据、两次退出、盘后权益点和评估均成功，缺一项即为 `operations_blocked`。运行日优先读取已有交易所日历缓存，无可信缓存时保守使用工作日兜底。评估器把计划/补跑的同一槽合并为最终决策周期，忽略系统自动退出，并按五阶段统计“观察候选→进入决策池→模型 BUY→实际 BUY”；延迟成交的最终记录继承原槽候选证据，完整空候选池有效，schema 缺失或内部矛盾则逐字段诊断。每个实际 BUY 还必须在决策和耐久成交两侧一致保存模型请求股数、确定性最大许可股数、风险上限利用率、约束上限和开仓/加仓标记；拒单保存稳定类别和原因，在连续风险输入尚不完整时不伪造精确上限。报告按五阶段聚合成交定仓利用率与拒单类别，任一已成交订单缺失或两侧不一致都会阻断质量门。定时决策或自动退出的耐久账本写入失败会使对应任务失败，不以进程已走完替代证据。首次入场的五阶段代码、中文标签、顺序、入口策略和行业必须完整；此后每次主线扫描按时间更新持仓阶段路径，实际 SELL 冻结退出阶段。完成生命周期必须覆盖其间每个实际运行日，并通过入口时间、路径段、退出时间和统一阶段定义校验；报告同时按入口阶段、退出阶段、完整路径和行业分组。运营复核仍在 30 笔完成交易或满三个月后开放，但成效声明必须有至少 30 笔完整可归因生命周期，同时满足观察胜率不低于冻结的 59.29% 历史参考、交易级 Wilson 95% 下界高于 50%、首次入场日期×行业的唯一簇数与 Herfindahl 有效簇数均不少于 30、簇等权胜率不低于历史参考且其 95% 下界高于 50%、费用后交易级与簇等权平均净收益为正；账户层还必须无非牛牛/未知成交、每日盘后权益完整、组合收益为正、最大回撤不超过 6%、收益/回撤不低于 1，并通过全部运行日及机会漏斗质量门。三个月但交易不足只允许复核频率和运行原因。旧 payload、阶段错配、状态层独有成交或字段缺失会得到 `data_quality_blocked`。后续代码或配置漂移只写诊断并阻断队列晋级，不覆盖原锁或把前后交易混为同一协议。盘后评估 Cron 只读账户账本并原子更新私有聚合报告；既不回写账户，也不自动修改生产策略。

协议 v18 的连续风险执行有两个受限例外：牛牛 BUY 在其他检查都通过、且模型请求超过正数整手风险上限时裁到上限；模型直接发出的牛牛 SELL 在请求超过正数整手 T+1 可卖量时裁到可卖量。BUY 执行 schema v2 要求决策副本、持仓入口上下文和耐久成交三方一致；SELL 执行 schema v1 在耐久成交中校验模型请求、当时可卖量、实际股数与裁单布尔值。需要裁单但可卖量为零或非整手、其他硬失败、系统自动退出及其他战法仍保持原有失败关闭或退出语义。
协议 v18 还把牛牛试仓日线 V 型恢复比 `[0.60, 2.00)` 作为策略身份的一部分冻结：评分域与交易域都复用 `strategies.policy.niu_reversal_recovery_blocker`，避免研究过滤、Dashboard 候选和成交前复核形成三套边界。协议身份显式包含上下界，历史参考胜率为 59.29%。
协议 v18 同时冻结领涨的主线内前 20% 与题材当日强度 60 下界，以及启动只接受跨日延续 `emerging` 的状态约束；评分域和交易域分别复用 `strategies.policy` 中的共享 blocker，已确认 `mainline` 不能再绕回启动身份。
协议 v18 还把酝酿试仓延续门写入策略身份：题材强势股数不少于 6，或酝酿状态连续至少 3 个交易日；每日最多 2 个试仓、单票绝对上限 6.25%。`strategies.policy.niu_reversal_continuation_blocker` 在评分域和交易域失败关闭，单笔权益风险预算不变。
漏斗中的实际 BUY 以耐久成交账本为准，并与决策 payload 的执行副本交叉核对；任一方向的缺口都保留独立一致性诊断并阻断证据晋级。
冻结范围同时包含前向 Cron 表达式、耐久数据库/恢复状态的有效路径和调度/存储/评估证据链源码。命令行 `--as-of` 只用于可重复的报告截止日；协议文件的冻结时间与起始日前重冻判断只接受实际墙钟时间，防止起始日后通过回填旧截止日覆盖漂移锁。

牛牛战法把题材状态解释为有序生命周期“主线酝酿 → 主线主升 → 主线高潮 → 主线分歧 → 主线退幕”，并与执行动作“牛牛试仓、牛牛启动、牛牛领涨、牛牛转强”分离：酝酿期只允许小仓试错，主升早段只允许尚待正式确认的 `emerging` 主题走启动，已确认 `mainline` 必须改走领涨；高潮期仍允许满足领涨或企稳转强条件的核心股开仓，同时继续执行持仓锁利；分歧期龙头可继续领涨，调整后的核心股只有企稳收复后才归入转强，持续回落不触发买点；退幕期只退出不开仓。牛牛不设固定单日涨幅上限，成交前只拒绝实际执行价达到对应板块涨停价的买单，其他阶段、形态、结构止损和组合风险门槛保持不变。确认主线达到 78 分才标记为高潮；题材阶段按连续交易日状态因果推进，主升减弱先进入分歧，明确退幕后出现新的候选或主线证据才开启新一轮。回测使用独立的策略组合状态机：以 100 万元独立初始资金运行，收盘产生信号后于次日开盘按牛牛动态风险预算定仓，并严格执行每个交易日最多 2 个新仓、最多 5 只持仓、单票/主题/总仓/现金储备约束。试仓入口只接受 `candidate/emerging` 早期题材，`candidate` 中已成为强势股的名称等待启动确认，成熟题材改走启动/领涨/转强；牛牛领涨必须处于主线内前 20%，主升/高潮还要求题材当日强度不低于 60，分歧则以个股持续强势核心替代矛盾的全题材强度门槛。同一股票命中多个动作时，可执行策略优先于被硬门槛阻止的高分策略。v20 允许原试仓/启动仓在浮盈 2%～12%、生命周期仍为主升且个股仍为强势领涨时分两级加仓：跨日延续的 `emerging` 启动先向 10% 上限加一次，确认 `mainline` 领涨后再向 20% 上限加一次；浮盈超过 12% 不追，首次非亏损高潮减仓 1/3。v21 在确认领涨后追加无固定次数的因果波段循环：距本轮收盘高点回落 1 ATR，或连续 3 个交易日未创新高且回落不少于 0.25 ATR，先减仓 1/3；只有随后从减仓价收复 0.5 ATR、生命周期重新处于主升且个股恢复强势领涨，才按动态风险上限补仓。补仓会重置周期，下一次加仓必须由新的独立回撤重新武装；分歧可触发减仓，但未修复分歧、高潮和退幕不能补仓。每个买入批次独立保留交易日，卖出仅使用 T+1 可售数量。持仓逐日回放结构止损、主线/龙头转弱、阶段时间退出、首段盈利保护、余仓成本保护和 2ATR 跟踪退出；试仓所属题材首次确认退幕即退出。进攻/修复入场的试仓在 0.75R 减仓 50%，轮动入场试仓及成熟路径在 1R 减仓 45%；首次建仓行情在持仓内冻结，阶段升级不会改写。完成卖出后同股可依据新信号再次买入，不使用固定冷却期代替持仓。组合状态机只使用各交易日收盘前已经取得的数据，不读取或修改模拟账户。日 K 无法还原盘中精确触发顺序：结构止损使用最低价并按止损价或跳空开盘价估算，阶段对应的 R 目标使用最高价并按目标价或跳空开盘价估算；同一根 K 同时触发时保守地先执行止损，其他完成 K 线后确认的规则仍按收盘价估算。尚未提供确定性卖出状态机的其他策略仍保留固定持有期事件研究模式。

多概念股票在评分时按动作选择相容的题材画像，而不是四个动作共用一个预先固定的概念；主/次主线只参与排序展示，不再排除其他已确认分支。历史回测拒绝诊断按自然月输出相对阈值敏感性、逐项/门槛族消融和各题材龙头覆盖，使频率问题可以在不自动改写生产风控的前提下复现。

牛牛 v27 把分类和交易归因建模为两个字段：东方财富 `f100` 写入事实 `industry/sector`，动作相容的 `f103` 分支写入 `signal_theme`。一个股票可保留多个题材成员关系，但当前题材强度、题材内排名、同题材个股共振和当日排名只产生 75% 当前证据，前序交易日快照按 0.75 衰减形成 25% 历史先验；归因权重在股票内归一化为 1，避免多标签重复计算叙事信用。Practice 首次成交冻结 `entry_theme`、分类来源、归因分数/权重和历史先验，持仓以 `active_theme` 承担题材容量与生命周期；替代题材必须处于有效生命周期、归因领先当前题材至少 10 分并连续两个交易日成立才可切换，`entry_theme` 永不回写。严格前向 v27 因此按首次入场日期×入场题材建立独立簇，缺少题材或归因证据即失败关闭；回测协议同步为 v28。

牛牛 v29 把归因移动到题材聚合之前。东方财富 `f103` 只生成候选分支；每个“股票×题材”先使用排除该股票后的同题材强势率、超额上涨广度、5/20 日趋势、同群方向和排名形成当前证据，再与前序因果先验组合。这条题材链路不发起消息面检索，消息摘要也不修改候选分支、归因或题材总分。多概念分支经 softmax 分配且允许保留未归因质量，因此一只股票不会再以完整权重同时抬高全部静态标签。题材强股、等效样本、成交额、结构广度、今日强度和领涨股使用归因权重重算，今日广度再按有效样本向全市场广度收缩；公开 Top 5 将高度重叠的标签折叠为关联题材。题材上下文 schema 升级为 v10，v9 快照不能提供跨日确认；严格前向和管理员回测协议分别升级为 v29/v30。

牛牛 v30 进一步用 20 日市场中性化收益波形区分同一股票的多个 `f103` 候选。计算先扣除每个交易日的全市场中位收益，再取排除目标股票后的同题材成员中位超额收益，与目标股票超额收益计算相关性；相关性按该股票全部候选题材的相对位置收缩后进入当前归因。该计算只读取已有日 K 与分类快照，不请求消息、不调用大模型。上下文 schema 为 v11，专用缓存为 v9，严格前向/回测协议为 v30/v31。

牛牛 v31 将“题材归因资格”和“题材内龙头排序”拆开。普通分支仍须达到 15% 归因权重；每只股票归因分最高且不低于 60 的首要题材可作为唯一的低份额例外，避免多标签数量机械稀释真实主线。通过资格后，结构龙头按原始 `strong_score`、今日龙头按当日涨幅排序，归因分只负责同值次序；题材广度、成交额、集中度和有效样本仍按归因权重聚合。回测用真实次日开盘校验结构资格，模拟滑点只影响成交与定仓。上下文/专用缓存 schema 为 v12/v10，严格前向/回测协议为 v31/v32。

Dashboard 只用单线程编排回测任务，实际计算在一个低优先级独立子进程中执行；任务完成或取消后由操作系统完整回收行情、题材截面和评分中间态内存。每个策略当前任务的创建状态、分阶段进度、单日耗时、ETA 和最终结果原子保存到私有运行目录 `backtesting/`；浏览器只轮询受保护的服务端状态接口。新任务覆盖同策略上一轮结果，服务重启后已完成任务直接恢复，执行中的任务从头重新排队。历史 K 线按东方财富、腾讯、新浪顺序降级，其中新浪只参与不复权请求。牛牛和板块潮汐的主分类来源是东方财富全市场批量接口：牛牛按 `f103` 概念做多标签聚类，个股没有概念时才使用同源 `f100` 行业；板块潮汐使用 `f100` 行业。完整响应原子写入私有最新快照和按日归档；刷新失败时优先回退已校验的东方财富旧快照。仅在首次部署等没有任何有效东方财富快照时，已启用且配置密钥的问财数据源才会完整分页获取同花顺行业与概念作为备用快照；备用结果必须通过总量与去重代码完整性校验，使用独立来源和缓存标识，不与东方财富分类混合，两个来源均不可用时回测明确失败。选股回放带按回测协议、日期范围、行情源、复权方式、可选股票池、分类快照和实际历史行情内容寻址并压缩缓存；调整定仓、退出等执行参数时可跳过题材截面重建与评分，损坏或不匹配的缓存自动降级为重算。进度明确区分题材截面重建、策略评分和持仓退出回放。用户终止任务时，Dashboard 会终止对应的精确子进程并立即释放执行位。

上图表达主要依赖方向，不表示各包完全互不调用：例如 Dashboard 会编排扫描和模拟交易，交易层会读取策略规则、行情与存储接口。领域包不能反向导入根启动入口；`strategies/` 不应主动请求行情或写账户，`market_data/` 不应判断买卖，`storage/` 不应实现策略评分。进程锁、长生命周期缓存、路径与环境配置放在相应服务组合层；可复用计算函数优先接收显式参数。这样既能独立测试，又能保留调用方对旧模块全局值进行替换的兼容行为。

## Dashboard Web 与增量读模型

Dashboard 使用 Vue 3 + Vite 和 FastAPI/Uvicorn，并保持单进程、单监听端口及原页面布局。高频展示读取与服务端计算解耦：

- `public_projection.py` 只接受显式源数据，并用字段白名单生成展示模型；
- `public_snapshots.py` 原子发布内容寻址对象、manifest 和 latest 指针；
- `projection_service.py` 在后台固定频率读取服务端状态，浏览器轮询不会触发交易、行情或历史重算；
- 候选与题材投影分别读取 `practice_candidates_latest.json` 和 `niuone_mainline_summary_latest.json`；二者排除全市场题材上下文和逐股归因状态，并按文件身份、大小与纳秒修改时间复用解析结果。完整扫描缓存继续供交易、分钟题材连续性和旧入口使用；小型快照缺失或落后时只读取一次完整缓存并自动补建；
- `fastapi_app.py` 是唯一 HTTP 监听者，只组合中间件、Vue 构建、共享缓存响应和领域路由；
- `routers/` 显式声明 system、messages、market、practice、admin 五组浏览器接口；
- `security.py`、`visit_stats.py`、`response_cache.py` 接收显式状态和路径，分别实现访问控制、统计持久化和带失效代次的并发 JSON 缓存；
- `server.py` 的既有后台函数仍由 FastAPI 组合层复用，但其中已不存在 `BaseHTTPRequestHandler`、`ThreadingHTTPServer` 或静态页面分发；
- `web/` 保存 Vue 组件、Vite 配置和依赖锁，生产产物由 FastAPI 从 `web/dist/` 提供；
- Vue 已接管主题、合规弹窗、版本状态、栏目 bootstrap 与路由、最后刷新时间、全部公开栏目、完整模拟账户及管理页；旧 `frontend/*.html`、`frontend/dashboard.js` 和 `frontend/admin.js` 已删除，`frontend/` 仅保存 Vue 复用的样式。模拟账户拆为账户概览、持仓/卖出卡片、收益曲线、交易日历、操作日志、规则、盘面总结和候选股组件，数据层共享公开投影订阅并按区块摘要刷新。FastAPI 显式声明全部浏览器 API，未知路径直接返回 404；管理员会话、操作请求头、请求体上限与分级限流语义保持不变。
- “题材强度”计算使用完整研究快照 `niuone_mainline_latest.json` 和分钟行情快照 `niuone_mainline_minute_latest.json` 保持跨日与逐股归因连续性，页面和公共投影只读取由它们派生的 `niuone_mainline_summary_latest.json`。共享定时或手动交易扫描结束后会另启 `--niuone-mainline-only` 全市场研究任务，它忽略当前交易策略且只更新完整题材缓存及对应摘要，不覆盖候选缓存或触发买卖。Dashboard 在盘前通过 `--prewarm-kline-cache` 把全量非 ST 股票最近 120 根腾讯前复权日 K 原子写入私有 SQLite；冷启动时 readiness 编排器立即补齐过期或缺失股票并持久化进度。交易扫描达到配置覆盖率后只读取本地历史，不在交互链路逐股回源；同一运行目录的预热和完整扫描由跨进程租约互斥。`/healthz` 只表达服务存活，`/readyz` 表达运行目录与市场数据可用性，结构化状态同时经 `/api/system/data-readiness` 提供给 Vue。市场宽度采样器默认每 30 秒（可配置为 30～600 秒）取得一份覆盖有效的逐股报价并交给题材快速计算器，后者只读取本地日 K、行业映射和最近完整研究扫描的慢速确认分量，不重复请求腾讯或新闻模型；CPU 密集计算及大型快照序列化在有 180 秒硬超时的隔离子进程执行，Dashboard 主进程始终可以返回上一份有效读模型。若完整选股、独立题材研究或日 K 预热正在运行，分钟刷新继续合并行情但让行重型任务；其他时段若该全市场计算耗时接近采样周期，分钟编排器按上一轮总耗时自适应冷却，把重算任务限制在约 25% 的单核占空比，市场宽度本身仍按原间隔采样。快速计算覆盖不足、报价过期或失败时保留上一份有效快照；公开页总是选择生成时间最新的有效题材结果。页面分别展示不改变交易门槛的“今日前5”和用于跨日主线确认的“结构前5”：今日强度仍由上涨广度 45%、涨幅至少 3% 的占比 25%、涨幅至少 5% 的占比 15% 和正中位涨幅 15% 组成，但四项输入先按个股题材归因权重聚合，广度再按有效归因样本向全市场广度收缩；实时涨跌幅原始及归因覆盖均至少 80%、原始报价不少于 3 只且归因样本不少于 1.5 时才参与排名。结构分继续使用 5 日、20 日、量能、均线、归因龙头与跨日延续。分钟编排层另外读取东方财富概念板块涨幅榜前 100，并按规范化后的精确题材名称把即时排名、上涨广度和领涨股附加到“今日前5”；该字段位于因果题材上下文之外，采用 60 秒缓存、10 分钟内陈旧回退和失败退避，既不改变 NiuOne 排序，也不进入跨日状态、回测或交易。`/niuone-mainline` 只消费字段白名单读模型，因此策略切换不会影响题材更新，同时逐股行情、原始个股上下文、SQLite 缓存和消息数据不会下沉到浏览器。
- 浏览器先检查轻量 latest 指针，只在区块摘要变化时加载对应数据；完整模拟账户历史仅在用户打开缺少分时数据的日历日期时按需读取，成功后本页面会话不再重复下载，失败最多每 5 分钟重试一次。
- Vue 资金流动画请求使用 `compact=1` 字段投影，服务端仅返回节点标识、名称、净额、采样时间和控件配置；完整响应仍保留给显式请求它的 API 客户端。

`/admin` 可以与公开页面通过同一域名访问，但所有配置读取、修改和测试操作仍必须经过管理员会话、限流与操作请求头校验。
