# 策略研究说明

简体中文 | [English](README_EN.md)

本文档集中说明 NiuOne 中用于研究实验的信号筛选、模拟决策和复盘机制。相关能力仅运行在本地研究与模拟环境中，不连接券商账户，不执行真实资金交易，也不构成投资建议。

## 1. 研究流程

NiuOne 将研究流程拆分为四层：

1. **候选生成**：根据当前启用的规则扫描公开行情数据，形成待观察样本。
2. **信息补充**：按需聚合指数、板块、资金、市场热度和近期消息。
3. **模拟判断**：结合规则约束、账户状态与可选模型输出，生成模拟记录。
4. **归档复盘**：保存输入摘要、来源状态、模拟操作和结果，便于后续检查。

策略输出是实验性信号，不应作为真实交易依据。行情源或模型源暂时不可用时，系统会记录来源状态，并按当前可用信息继续或跳过对应流程。

## 2. 独立策略

设置页直接选择一套当前策略，一次只激活一套。基础策略、Z 哥、李大霄、板块潮汐、牛牛战法和预设文字策略是同级、互斥的独立策略；每套策略独立提供候选范围、评分、买入、卖出、仓位和模型 Prompt。未启用策略不会进入本轮新开仓扫描或决策上下文。

切换策略不会篡改历史持仓归因。当前激活策略只控制本轮新开仓 BUY；已有持仓继续按买入时记录的 `strategy_mark` 加载原策略退出纪律。每轮都先刷新持仓，再处理新候选；候选为零或日内亏损预算触发时，SELL/HOLD 检查仍继续。新版文字策略在创建阶段仅调用模型细化一次；用户确认激活后，选股、买前复核、持仓监测和卖出全部由本地冻结规则执行，运行期不再调用模型。每个持仓绑定建仓时的不可变版本，后续激活新版本不会改写已有持仓。缺少版本、事实、指纹或审计证据时失败关闭，不猜测买卖。

### 2.1 用户：如何启用与触发

1. 在设置页把“当前独立策略”设为“板块潮汐”，对应配置为 `DASHBOARD_ACTIVE_STRATEGY=sector_tide`。该设置可热应用，保存后从下一轮扫描开始生效，不需要重启 Dashboard。
2. 新候选和模型买卖复用实战页面的共享调度计划，由 Dashboard 进程内置调度器按 `DASHBOARD_PRACTICE_SCHEDULE_TIMES` 触发；板块潮汐没有另一套独立选股定时器。
3. 如需立即运行，可在实战页面点击“手动触发选股及买卖策略”。一次完整执行包含全市场扫描、候选生成、模型判断和执行层风险复核。
4. 09:25 的扫描只使用竞价结果形成候选，不会在 09:25–09:30 静默期模拟成交；可执行动作会等待 09:30 后重新检查价格、交易时段和风险限制。

调度职责分为两个进程：

| 工作 | 进程 | 主要配置 | 行为 |
|---|---|---|---|
| 选股和模型买卖 | Dashboard | `DASHBOARD_B1_SCHEDULE_ENABLED`、`DASHBOARD_PRACTICE_SCHEDULE_TIMES` | 到点或手动触发后先检查全部已有持仓的原策略退出，再把当前激活策略候选送入模拟决策；零候选仍执行持仓退出检查 |
| 本地自动退出 | Cron Scheduler | `DASHBOARD_B3_EXIT_TIME`、`DASHBOARD_TIME_EXIT_TIME` | 在配置时间刷新持仓行情并检查结构止损、退潮、时间窗、策略专属 R 倍数减仓和 2ATR 等规则 |

自动退出是离散时间检查，不是券商条件单或逐笔行情实时监控。页面刷新只读取状态，不会触发自动成交。切换到其他策略后，板块潮汐不再产生新候选，但已有板块潮汐持仓仍按保存的策略标记接受退出检查。

### 3.1 基础策略

- **突破确认**：平台或前高突破后回踩站稳，作为趋势确认样本。
- **趋势回踩**：强趋势标的回踩 BBI / EMA 不破，作为低位观察样本。

### 3.2 Z 哥规则组

该规则组参考 [`zettaranc-skill`](https://github.com/lululu811/zettaranc-skill) 中整理的公开方法，当前包含：

- **少妇 B1**：关注 J 值低位、N 型上移、缩量回调和 BBI 约束。
- **B2 确认**：观察 B1 后的放量阳线确认，并过滤明显滞后或偏离 BBI 过远的样本。
- **B3 中继**：观察 B2 后的小阳线或十字星，以及分歧转一致特征。
- **超级 B1**：观察放量破位后的缩量企稳，以及 J 值仍处低位的形态。

选股评分同时复用 Dashboard“资金流动”页的东方财富行业板块“今日主力净额”快照。个股所属行业进入主力净流入前十时，第 1 名增加 1.50 分，之后每降一名递减 0.15 分，第 10 名增加 0.15 分；显示分仍保持 10 分制上限，排序分保留封顶前的行业加分，因此技术分同为 10 分时仍优先行业排名更高的个股。行业标签缺失、名称无法唯一匹配、榜单为空、请求失败或只能读取过期缓存时保持原技术分，不把缺失数据当成负面信号。

退出与风险规则包括：前低或入场 K 线约束、防卖飞评分、分批退出、S1 / S2 / S3 逃顶、出货形态、白线 / BBI 破位、峰值回撤、ATR 吊灯保护，以及 B2、B3、超级 B1 的时间约束。

少妇 B1 使用“硬退出优先、软退出确认”的持仓状态机。买入后至少观察 3 个 A 股交易日，开盘前 30 分钟只允许收盘确认的结构止损、白线死叉黄线、白线连续两日破位和高置信度出货等硬退出。盈转亏、单次 BBI/评分转弱、峰值回撤、ATR 吊灯和时间效率属于软信号：行业主力净流入或下跌缩量时继续持有；普通软信号需在不同检查窗口连续出现两次才减半；行业主力净流出与预测放量下跌同时出现时可直接确认减半。缺失、失败或过期的资金流与量能数据保持中性，剩余趋势仓仍等待结构性退出。

行业方向复用每轮扫描已经取得的东方财富行业主力净额快照。个股预测量比使用实时累计成交量、近 20 个已完成交易日成交量中位数，以及 Dashboard 现有的大盘同时间成交进度/全天成交额预测推导，不新增独立行情请求。模型对少妇 B1 输出的 `SELL` 只作为建议，执行层会降级为 `HOLD`，实际卖出统一由本地持仓状态机执行。

### 3.3 李大霄规则组

该规则组参考 [`li-daxiao-skill`](https://github.com/sherjy/li-daxiao-skill) 的政策、价值、底部发育、逆向情绪和杠杆风控框架，并使用高流动性蓝筹、低位企稳、低换手、缩量低波动、反追高和风险标的过滤作为可执行代理信号。

### 3.4 板块潮汐

板块潮汐每轮先对同一批高流动性股票生成一个横截面快照，再按“市场状态 → 行业潮位 → 板块内个股强度”筛选，行业是硬门控而不是个股分数的加分项。

每轮只在滚动最新龙虎榜快照的日期精确等于扫描日前一 A 股交易日时读取，把主榜净买卖、买卖前五全部席位净额和机构席位净额作为确认因子；同日尚未完整发布的数据或更早日期快照均保持中性，不做任意日期回退。行业潮位最多调整 ±2.5 分，个股综合分最多调整 ±0.35 分，二者合计对 10 分制候选分的影响不超过 ±0.45。未上榜不视为负面，快照缺失或席位不完整时按可用主榜信息或中性值降级；若个股当日涨幅超过 7% 或距 EMA20 超过 1.5 ATR，龙虎榜正向加分会被抑制，负向风险提示仍保留。该因子用于候选排序和历史检验，不代表已经证明会提升未来胜率。

扫描同时读取仅对当日有效、且对应最近一个已完整收盘美股交易日的隔夜摘要：整体风险偏好最多调整 -0.15 至 +0.05 分，摘要中明确映射到 A 股行业的美股板块表现最多再调整 ±0.15 分。完成首轮技术与行业评分后，只对排名前五的板块潮汐候选查询最近 3 天个股重大消息，结构化为利好、利空或中性；利好调整 +0.15 分，利空调整 -0.30 分，缺失、过期或无法识别时保持中性。龙虎榜、隔夜美股和消息面三类外部确认合计限幅为 -0.90 至 +0.60 分；正向信号仅在 A 股行业本身处于领先或改善状态、且个股未触发追高条件时生效，负向风险始终保留。扫描阶段的消息记录会写入候选缓存供模型决策直接复用，避免同一轮重复请求。

- **主线领航**：进攻或轮动行情中的领先行业，个股须处行业前 20%，只做突破或 EMA20 附近缩量回踩；8% 是单票绝对上限，实际仓位由动态风险预算决定。
- **轮动初升**：行业排名和广度快速改善，个股须处行业前 30%，拒绝单日涨幅超过 7% 或距 EMA20 超过 1.5 ATR 的追高；6% 是单票绝对上限。
- **冰点修复**：仅在防守解除后的修复状态做率先转强行业，T+2 未确认退出；4% 是单票绝对上限，实际仓位由修复状态风险预算决定。

风险预算随市场状态切换。进攻、轮动、修复的单笔权益风险预算分别为 0.30%、0.20%、0.10%，策略内组合未实现止损风险上限为 1.50%、0.80%、0.30%，单行业风险上限为 0.60%、0.40%、0.20%；对应总仓上限为 45%、30%、15%，行业敞口上限为 12%、10%、6%，防守状态全部归零并禁止新仓。同一行业最多 2 只。有效损失距离按“结构止损距离 + max(近 60 日向下跳空 P95，0.5 ATR 占比) + 0.20% 费用滑点”计算，实际单票上限取风险预算反推仓位与注册绝对上限 8%/6%/4% 的较小值。行业分数连续两个交易日低于 55、市场复合风险硬停止且行业转弱、或策略时间窗未兑现时退出；盈利达到 2R 先减半，余仓使用 2 ATR 跟踪。行业资金流缺失时使用量能参与度作为明确标记的后备指标，不会把缺失值当作净流入。

#### 用户：仓位和退出如何执行

- 模型必须为每条 BUY/SELL 给出 100 股整数倍数量。执行层不会替模型补默认仓位；除牛牛安全 BUY 裁到正数风险上限、以及牛牛模型 SELL 裁到正数整手 T+1 可卖量这两个受限例外外，不会把超额订单自动缩小后成交。
- 候选必须有有效结构止损，结构距离须同时不超过 6% 和 1.5 ATR；缺少历史跳空/ATR 缓冲时禁止买入。
- 实际买入数量会依次接受单票动态上限、市场总仓、同行业数量、行业敞口、单笔风险、策略组合风险和策略内行业风险检查。牛牛有效 BUY 若仅是模型股数高于正数风险上限，会向下裁到该 100 股整手上限成交；资格、数量、主题容量、风险输入缺失或风险上限为零仍整笔拒绝，并在决策日志中记录原因。其他战法保持原有整单拒绝语义。
- 市场状态预算是板块潮汐的最高许可值；全局盘面指引、`DASHBOARD_MAX_TOTAL_POSITION_PCT` 或现金缓冲更严格时，执行层取其中最小值，不会因全局配置更宽松而放大板块潮汐预算。
- 总仓和行业敞口按整个模拟账户计算；同行业数量会计入账户中所有带同一行业标签的持仓。组合止损风险和行业止损风险只汇总板块潮汐策略持仓。
- 主线领航 5 个交易日未兑现、轮动初升 3 个交易日不延续、冰点修复 T+2 未确认，均在尾盘时间检查中退出。
- `2R目标 = 平均成本 + 2 ×（平均成本 - 入场结构止损）`。首次达到 2R 减半，余仓在跟踪线高于成本后按 `持仓最高价 - 2 × ATR` 退出。

#### 开发者：状态、评分和数据契约

市场状态由同一轮扫描快照生成。市场综合分使用核心指数趋势 25%、涨跌家数广度 25%、中位涨跌幅 15%、涨跌停结构 15%、样本 20 日趋势 10% 和量能参与度 10%。状态机口径如下：

| 状态 | 判定 |
|---|---|
| `offensive` | 市场分数 ≥65 且上涨广度 ≥55%，并通过状态确认 |
| `rotation` | 未触发防守且不满足进攻条件，并通过状态确认 |
| `recovery` | 上一确认状态为防守，本轮原始状态已经解除防守 |
| `defensive` | 市场分数 <40 时进入最低风险档；复合硬停止也会进入防守并禁止新仓 |

复合硬停止要求指数破位、市场广度破位和跌停扩散同时成立。除硬停止外，状态变化通常需要连续两轮出现同一原始状态；首次没有历史状态时直接采用本轮结果。

行业评分权重及潮位阈值：

| 因子 | 权重 |
|---|---:|
| 20 日相对强度分位 | 25% |
| 5 日相对强度分位 | 15% |
| 排名加速度分位 | 15% |
| EMA20 以上广度 | 20% |
| 20 日新高占比 | 10% |
| 行业资金流；缺失时使用量能参与度 | 10% |
| 行业成交额流动性分位 | 5% |
| 前一交易日龙虎榜确认 | 基础分之外限幅 ±2.5 分 |
| 最近已收盘美股盘面与行业映射 | 个股综合分之外限幅 -0.25 至 +0.20 分 |
| 前五候选最近 3 天个股消息面 | 个股综合分之外利好 +0.15、利空 -0.30 分 |

行业至少需要 3 个有效成员，个股至少需要 55 根日 K。`leading` 要求行业分数 ≥75 且 20 日相对强度分位 ≥70；`improving` 要求分数 ≥65、排名加速度 ≥15 且 5 日相对强度分位 ≥65；分数 <45 或 20 日相对强度分位 <35 为 `lagging`，其余为 `weakening`。

主线领航、轮动初升、冰点修复的入选评分阈值分别为 8.0、8.2、8.5；板块内强度分位分别至少为 80、70、70。扫描结果必须把 `market_regime`、行业潮位、龙虎榜快照日期/可用性/限幅调整、隔夜美股交易日/风险偏好/行业映射、消息面标签/摘要/抓取时间、结构止损、跳空缓冲、有效损失距离和各级风险预算随候选写入缓存，执行层会用实时成交价和共享风险参数重新计算，不信任模型自行给出的风险数值。

核心实现位于 `app/strategies/scoring/sector_tide.py`、`app/strategies/sector_tide_risk.py` 和 `app/trading/practice_trader.py`。专项回归入口为 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_sector_tide_strategy.py' -v`，全量验证入口为 `./scripts/validate.sh`。

### 3.5 牛牛战法

牛牛战法先在同一轮全量有效行情横截面中为每只股票计算强势分，再按行业聚合为可审计的“主题代理”。强势分综合 20 日与 5 日相对强度、量能参与、成交额相对分位、EMA20/EMA50 趋势和 20 日新高；其中 20 日/5 日强度权重为 30%/20%，量能参与/成交额分位为 15%/15%，趋势/新高各为 10%。成交额表示真实资金参与度，不参与仓位上限计算。系统另外按“全市场成交额分位 65% + 题材内成交额分位 25% + 量能参与分位 10%”生成 0～100 的个股资金活跃度，供候选解释和前向审计。行业只是当前稳定的数据代理，不把名称相近的股票自动归为同一概念；后续接入可靠概念标签时可替换映射层，不改变状态和风控合同。

成熟主线路径新增确定性资金活跃门：牛牛领涨、牛牛转强和牛牛启动必须同时达到全市场成交额分位 ≥60、所选题材内成交额分位 ≥50；成交额数据缺失时失败关闭。该门不按市值大小机械加分，也不奖励单纯高换手，因此真实放量的小市值龙头仍可通过，而仅凭小流通盘形成高涨幅/高换手、绝对资金参与不足的股票不能进入成熟交易池。牛牛试仓保留早期发现能力，不受该硬门限制，但活跃度未确认时会标记“仅允许轻仓试仓”。

主题分由强股强度、强股广度、领涨梯队、资金参与、跨市场日期持续性和有界龙虎榜确认构成，不使用消息面。按强股强度与成交额生成贡献权重，并用有效强股数 `1 / Σ(weight²)` 与最大单股权重识别集中度；单只股票独强会受到惩罚，不能确认市场主线。题材强度页面另外展示归一化的“有效广度”，计算为 `有效强股数 / 题材有效样本数 × 100%`，便于不同规模题材横向比较；原始有效强股数仍用于状态阈值。系统允许输出 `mainline.mode=none`，不会为满足交易频率强行选出主线。

主题状态按 `candidate → emerging → mainline → diverging → fading/inactive` 迁移，但“扫描确认”与“交易确认”已分离：同一交易日无论扫描多少次，达到主线横截面标准也只记录为 `intraday_mainline` 日内观察，不直接授权买入。只有相邻交易日仍达到强势主题标准，并且前 5 只核心强股中至少 2 只延续，才确认 `mainline`；日期断档或核心股全部更换都会重置确认。确认主线要求主题分 ≥75、至少 3 只强股且有效强股数 ≥2.4；启动主题要求分数 ≥65、至少 2 只强股且有效强股数 ≥1.7。已确认主线转弱时先进入分歧或退潮状态，避免单次噪声直接改写持仓。

上述内部状态进一步映射为面向交易的五阶段：`candidate` 和未完成跨日延续的 `emerging` 属于**主线酝酿**；完成延续的 `emerging` 与普通强度的 `mainline` 属于**主线主升**；跨日确认且题材分数达到 78 的 `mainline` 属于**主线高潮**；`diverging` 属于**主线分歧**；`fading` 属于**主线退幕**。78 分取自主线分数分布的高强度尾部，不是按交易结果搜索出的最佳阈值。从未启动过的 `inactive` 不会被误标为退幕。五阶段与四动作现在共用一套生产硬路由：酝酿只允许牛牛试仓；主升只允许牛牛启动或牛牛领涨；高潮允许仍满足核心领涨或企稳转强条件的股票开仓；分歧只允许仍保持核心强度的牛牛领涨或企稳收复后的牛牛转强；退幕只退出。持续回落不产生买点。阶段按逐日数据因果推进：主升退回未延续状态时先进入分歧，高潮降回普通强度时也进入分歧，分歧继续减弱才进入退幕；明确出现 `fading/inactive` 后若重新出现候选或有效主线证据，才开始新一轮酝酿、主升或高潮，避免退幕后新周期被永久误标，也避免主升噪声回退成第二次酝酿。评分、Dashboard 候选和历史回放均调用同一个阶段动作校验器，不再把生命周期只当影子归因标签。

一只股票同时属于多个东方财富概念时，四个动作分别选择与自身阶段相容的概念画像：试仓寻找酝酿分支，启动寻找跨日延续的 `emerging` 分支，领涨/转强寻找已确认主线或有效分歧分支。不会再先全局固定一个概念、再把其他分支的龙头按错误阶段拒绝。页面上的主/次主线仍用于展示和排序，不再作为“只有前两个题材才可交易”的资格门槛；主题风险、同主题持仓、每日新仓和总持仓限制继续在组合层约束实际成交。

- **牛牛试仓**（兼容内部 ID `niu_reversal_probe` 和旧名“牛牛反转”）：只参与主线酝酿，即 `candidate` 或尚未完成跨日延续的 `emerging`；一旦进入主升或分歧便不能再用低确定性的试仓入口。`candidate` 中已经达到 `stock_strong` 的名称仍须等待牛牛启动确认。在最近 30 根日 K 中还须形成个股区间 V 型趋势：左侧从阶段高点回落至低点至少经历 5 个交易日且跌幅 ≥8%；低点距当前 3～15 个交易日，右侧反弹 ≥6%、收复左侧跌幅须处于 `[60%, 200%)`，上涨交易日占比至少 2/3，当前收盘继续处于右侧近期高位。恢复比达到 200% 时个股已经超出早期试仓语义，评分与成交前复核都会失败关闭。题材还必须满足“至少 6 只强势股”或“酝酿状态已连续 3 个交易日”之一，避免瞬时、窄广度修复占用资金。入场价必须位于 EMA20 上方 1.0～1.5 ATR；每天最多保留评分最高的 2 只。阈值 7.6，单票绝对上限 6.25%，进攻/轮动/修复/防守的单笔风险预算固定为 0.35%/0.30%/0.25%/0.15%。
- **牛牛领涨**（兼容内部 ID `niu_leader` 和旧名“牛牛领航”）：可在主升、高潮，或已确认主线转为 `diverging` 后个股仍保持核心强度的因果分歧中参与。个股必须是主线前 20% 的核心强股，只接受有效突破或首次 EMA20 缩量回踩；主升/高潮仍要求题材当日强度至少 60，分歧阶段则以个股仍为强势核心和前 20% 代替与分歧定义矛盾的全题材强度门槛。突破路径按“收盘价超过前 20 日高点的 ATR 距离”复核，回踩路径仍按距 EMA20 复核；不设固定单日涨幅上限，实际执行价达到对应板块涨停价才拒绝买入，进攻/轮动的锚点距离上限仍为 1.5/1.25 ATR。阈值 8.0，单票绝对上限 30%。
- **牛牛转强**（兼容内部 ID `niu_pullback` 和旧名“牛牛承接/牛牛回踩”）：参与高潮或主线分歧；主题原始状态须为 `mainline/diverging` 且分数 ≥70，个股处前 30%，只接受 EMA20 附近企稳转强或重新收复，持续回落不触发买点。不设固定单日涨幅上限，实际执行价达到涨停才拒绝；进攻行情距 EMA20 上限为 1.25 ATR，轮动和修复行情为 1 ATR。阈值 8.2，上限 25%。
- **牛牛启动**：只参与主线主升中的早段，即已经跨相邻交易日延续、但仍待正式确认为主线的 `emerging`。主题一旦进入 `mainline`，即使分数仍低于高潮线，也必须改走领涨条件，不再用低门槛启动身份重复入场。至少两只核心强股必须保持连续，核心股突破或收复后只建观察仓，纯日内强势不得触发；分歧和高潮阶段不再走启动。突破路径按超过前 20 日高点的 ATR 距离复核，收复路径仍按距 EMA20 复核；不设固定单日涨幅上限，实际执行价达到涨停才拒绝，对应锚点距离仍不得超过 1.5 ATR。阈值 8.4，上限 15%。启动仍是观察仓，不能因为从酝酿进入早段主升就立即放大仓位。

资金活跃门升级后，题材上下文/专用缓存为 v13/v11，严格前向候选证据同步记录个股活跃度、全市场/题材内成交额分位和确认结果，协议升级为 `niuone-strict-forward-v32`；管理员回测升级为 `niuone-backtest-v33`。旧协议锁、报告和回测结果不得与新门槛证据混算。

面向用户的策略理由从 v33 起使用上下文安全的中文展示映射：内部阶段、角色和主线模式仍以英文枚举参与计算和兼容接口，只有中文策略上下文中的独立小写枚举会转换；专名、英文技术表达、错误文本、缩写和标识符不改写，二次取舍的嵌套理由也在持久化前转换。交易规则不变，但展示映射和提示词属于冻结证据链，因此严格前向协议升级为 `niuone-strict-forward-v33`，默认新队列从 `2026-08-13` 开始。

四个牛牛入口都不再按 4%/5%/7% 的固定单日涨幅线拒绝候选。实时模拟成交按前收盘价、板块涨跌停比例和交易所两位小数规则计算涨停价：只有实际执行价已经达到涨停才拒绝，低于涨停的股票继续接受题材、形态、ATR 扩张、结构止损和组合风险检查。历史回测同样在次日开盘达到涨停时记录 `open_at_limit_up`，不会把无法成交的封板开盘当成成交。

成熟路径在进攻、轮动、修复、防守状态的单笔权益风险预算分别为 1.50%、1.00%、0.60%、0.30%；牛牛试仓收紧为 0.35%、0.30%、0.25%、0.15%。策略内组合风险上限为 4.50%、3.00%、1.80%、0.90%，成熟路径单主题风险上限为 3.00%、2.00%、1.20%、0.60%；试仓路径的单主题风险上限为 0.70%、0.60%、0.50%、0.30%，题材敞口上限为 12%、10%、8%、5%；总仓上限为 70%、55%、35%、20%。防守状态允许按最低风险档开仓，只有复合风险硬停止禁止新仓。同一主题最多 2 只；每个交易日跨 Practice 决策轮次累计最多新开 2 只，策略同时持仓硬上限为 5 只，盘面与午盘前动态限制通常会进一步收紧到 3 只。牛牛试仓使用右侧最近 3 根日 K 的最低价作为确认止损，距离上限为 6%/2 ATR；领涨/启动的突破路径以突破位下方 0.5 ATR 为结构止损；转强、收复等路径继续使用最近结构低点。成熟路径仍按进攻 10%/2.5 ATR、轮动 8%/2 ATR、修复或防守 6%/1.5 ATR 复核。牛牛战法使用 14 日真实波幅简单均值，并在候选与持仓中显式记录 `atr_period=14`；历史字段 `atr20` 仅作为兼容别名保留。有效损失距离包含结构止损、跳空缓冲和 0.20% 执行缓冲，实际仓位由风险预算反推。防守入场的试仓与进攻/修复入场试仓相同，在 0.75R 先减仓 50%；轮动入场试仓和成熟路径仍执行 1R/45%。

Practice 仍要求模型明确给出 100 股整数倍订单。牛牛有效 BUY 若模型请求超过全部连续风险约束共同决定的正数整手上限，执行层只向下裁到该上限；不会放宽资格、持仓/主题容量、止损输入、现金或任何风险预算，上限为零仍拒绝。牛牛模型 SELL 若请求高于正数整手 T+1 可卖量，则按可卖量成交；需要裁单但可卖量为零或非整手时仍拒绝，系统自动退出与其他战法不变。严格前向 v20 会为每个实际 BUY 保存模型请求股数、实际股数、最大许可股数、是否裁单、上限利用率、约束上限和首次建仓/加仓标记；模型 SELL 另存模型请求、当时可卖量、实际股数和裁单标记，并在盘后校验不一致证据。市场、资格、容量、风险输入和风险上限拒单使用结构化类别。已成交 BUY 的决策副本与耐久成交必须一致，否则该前向样本不能通过数据质量门。首次入场行业也随生命周期冻结，供题材集中度诊断。历史回测默认仍是最大风险许可定仓情景，不等于模型订单回放。v20 同时冻结买卖裁单语义、每日牛牛新仓上限与跨轮计数口径，并从首次建仓开始耐久记录酝酿、主升、高潮、分歧、退幕的持仓路径与真实退出阶段，要求每个实际持仓运行日都有观察，供阶段到达率、转移与完整路径收益诊断。

v20 将 6.25% 明确定义为酝酿试仓的初始上限，而不是整段持仓的资金利用率。原试仓或启动仓浮盈处于 2%～12%、生命周期仍为主升且个股仍处于强势领涨梯队时，跨日延续的启动主线可在次一交易时段向 10% 上限加仓一次；主线完全确认后，可再向 20% 上限加仓一次。实际目标继续取风险定仓、主题/组合风险、现金和阶段上限中的最小值；浮盈超过 12% 不追仓，高潮、分歧、退幕不允许加仓。进入高潮且持仓不亏时自动减仓 1/3；原有 0.75R/1R 首段止盈、成本保护和 2ATR 跟踪继续生效。

v21 不再用“每级一次”表示确认领涨后的整段仓位管理。确认领涨仓距本轮收盘高点回落 1 ATR，或连续 3 个交易日未创新高且回落不少于 0.25 ATR 时，先释放 1/3；随后必须从减仓价重新上行 0.5 ATR、生命周期回到主升且个股恢复强势领涨，才补回风险预算允许的仓位。每次补仓重置本轮高点和横盘计数，只有下一次独立回撤才能再次触发，因此同一股票可多次减仓/加仓但不能连续上涨中机械补仓。已发生 0.75R/1R 首段减仓的持仓同样可等待新回撤后武装一次补仓。分歧可触发减仓，未修复分歧、高潮与退幕不允许补仓；单票、主题、组合、现金及 T+1 约束不变。

严格前向的运营复核门与成效声明门相互独立：满三个月但不足 30 笔只能检查交易频率和运行完整性。交易级门要求至少 30 笔完整可归因生命周期、点胜率不低于冻结的 59.71% 历史参考、Wilson 95% 胜率下界高于 50%，且费用后平均净收益、累计已实现盈亏和利润因子均高于盈亏平衡。v20 再按首次入场日期×行业聚类：唯一簇数和 Herfindahl 有效簇数均不少于 30，簇等权胜率不低于 59.71%、其正态 95% 下界高于 50%，且簇等权平均净收益为正；同日同业批量交易不能重复充当独立样本。最终“可人工复核高胜率且正收益声明”还要求起始日前冻结零持仓账户基线，队列内没有非牛牛/未知策略成交，每个实际运行日都有 15:00 后耐久权益点，组合收益为正、最大回撤不超过 6%、收益/回撤不低于 1，并且全天运行与机会漏斗 100% 完整；永不自动晋级。

龙虎榜和前五候选最近 3 天消息只作限幅确认：正向信息在追高时被抑制，不能把无日线 V 型结构或追高候选变为可买；明确利空仍降权。牛牛试仓所属题材首次确认 `fading/inactive` 或分数低于 55 即退出，3 个交易日未延续右侧趋势也退出；首次分级加仓仍须满足 v20 的主升、2%～12% 浮盈窗口和领涨质量门，v21 波段补仓则必须已有真实减仓、完成价格转强并重新通过主升强领涨门。成熟路径继续按结构止损、主题连续转弱、市场硬停止叠加退潮及领涨 5 日/转强 3 日/启动 T+2 未兑现退出。主线进入高潮且持仓不亏时先减仓 1/3；试仓若首次建仓处于进攻、修复或防守行情，盘中达到 0.75R 先减仓 50%；轮动入场试仓以及领涨、转强、启动等成熟路径仍在 1R 减仓 45%。首次建仓行情在持仓内冻结，后续扫描或阶段升级不会改写；首段兑现后的余仓止损抬到成本线并使用 2 ATR 跟踪。核心实现位于 `app/strategies/scoring/niuone.py`、`app/strategies/niuone_risk.py` 和 `app/trading/practice_trader.py`。专项回归入口为 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_niuone_strategy.py' -v`，全量验证入口为 `./scripts/validate.sh`。

Dashboard 的“题材强度”栏目（`/niuone-mainline`）是独立于交易范围和当前交易策略的全市场题材研究页，展示市场状态、跨日确认主线、日内领涨题材、强度最高的 5 个题材及核心股延续。日内强度只观察当日参与，不改变牛牛战法的跨日生命周期或交易门槛；牛牛试仓仍由个股日线区间独立判断。覆盖率按“有效进入题材聚类的股票数 / 全量参考池股票数”计算，不读取设置中的选股范围，也不展示交易候选、仓位或买入状态。未覆盖股票按互斥处理阶段标记为 K 线不可用或少于 30 根、历史不足 55 根、关键指标无效、行业映射缺失或其他数据不完整；旧快照没有原因明细时会明确等待下一次扫描补齐。Dashboard 默认在交易日 09:10 运行 `--prewarm-kline-cache`，把全量非 ST 股票最近 120 根前复权日 K 保存到私有 SQLite；盘中用批量实时行情追加或替换当天 K 线，仅对缓存缺失或日期过期的股票回源。市场情绪后台默认每 30 秒取得一份通过覆盖校验的腾讯逐股最新报价；题材快速计算器复用同一份报价，在进程内读取日 K 和行业本地缓存、沿用最近完整研究扫描的慢速确认分量，并独立写入 `niuone_mainline_minute_latest.json`。它不会额外请求腾讯、新闻模型或交易接口，覆盖不足或报价过期时也不会覆盖上一份有效结果。采样间隔可通过 `DASHBOARD_MARKET_BREADTH_SAMPLE_INTERVAL_SECONDS` 在 30～600 秒之间配置。每轮共享定时或手动交易扫描结束后，Dashboard 仍会在后台另启 `--niuone-mainline-only` 完整研究扫描；它固定使用牛牛题材算法和全量非 ST 参考池，只原子更新专用 `niuone_mainline_latest.json`，不会改变当前策略、候选缓存或模拟买卖。页面从分钟快照、完整研究快照和迁移期缓存中选择生成时间最新的一份。题材数量限制仅用于公开页面，专用缓存仍保留全部题材供跨日连续性判断。浏览器只能读取字段白名单生成的公开读模型，不直接访问逐股行情、原始扫描上下文或本地 SQLite。

上述名称仅用于标记项目中的规则实验，不代表相关原作者参与、认可或背书本项目。二次分发相关说明时，请保留对 `zettaranc-skill` 与 `li-daxiao-skill` 的引用。

### 3.6 文字策略闭环

管理设置页的“文字策略闭环”接受模糊自然语言。服务端用当前决策模型将它细化为 `selection`、`entry`、`exit`、仓位、候选上限和缺数据策略，但每个草案只允许成功细化一次。流式连接中断、空响应或不完整 JSON 会清空页面上的半截输出，并以一次完整响应请求有界降级；第一次本地编译失败则会把安全的 schema 错误反馈给一次创建期重写。对于原始文字中方向明确的今日/昨日成交量、最高价和最低价比较，本地完整性层会移除模型对这些字段生成的近似或畸形节点，再用 `market.value` 与 `offset_bars=0/1` 确定性重建 selection/entry，并把补全内容写入 assumptions 供确认；无法确定比较方向时仍失败关闭。模型常见的 `all/any.conditions` 会明确规范化为 `children`，错误仓位对象则不会被猜测换算。重试仍失败时只显示不含响应正文和密钥的明确错误原因，失败草案恢复为可重试状态。用户可审核完整 JSON、假设、歧义和特征依赖；点击确认时服务端还会核对计划指纹。激活采用两阶段提交：先写入不可变的待激活版本，再同步运行策略配置，最后原子替换活跃版本；中途失败会恢复草案并保留上一个活跃版本。

激活版本的本地执行路径是：

1. 在配置的 A 股范围内扫描全部具有有效行情的股票，按 `selection` 过滤后再应用 `candidate_limit`。
2. 从冻结执行计划提取每个阶段的 `required_features`，仅加载足够的 K 线并计算所需特征；不为 KDJ 策略预计算全部指标。`prompt-rules-v3` 在 KDJ、EMA、RSI 和 MACD 的明确递归预热窗口之上，为所有注册特征增加通用的 `offset_bars` 历史偏移，并把偏移量计入最小 K 线预算；执行计划同时冻结具体特征版本。已有 `prompt-rules-v2` 版本仍可历史重放。
3. 每次求值都执行数据合同：已收盘规则必须命中预期交易日，实时规则还必须有可解析的观测时间且未超过 `freshness_seconds`。日期错位、过期或缺失均把事实置为 `unknown`，不触发交易。
4. 买入执行前重新加载行情，校验选股审计指纹，重新求值 `entry`，再按冻结仓位规则模拟成交。文字策略的股数输出不能突破系统单票仓位、总仓位和最低现金硬上限，交易费用也纳入现金下限复核。
5. 建仓后把股票绑定到入场版本，每轮用该版本的 `exit` 规则监测；条件成立但 T+1 不可卖时标记待卖。真正退出前会精确读取对应审计记录，重放并核对版本、持仓绑定、计划指纹、代码和真值结果，通过后才卖出并释放绑定。
6. 选股、买前复核和退出每次都写入追加式审计，包含版本、计划 SHA-256、事实快照、数据质量、三态结果、证据树、动作意图与完整重放上下文。审计 JSON 以 zlib 压缩存储，完全相同的重试通过幂等键去重，但不丢弃不同观测时间的记录。

特征注册表当前支持 OHLCV、MA/EMA/BBI/KDJ/RSI/MACD/布林带、收益率、量比、波动率、ATR、区间高低点和回撤，后续指标通过带版本的注册项扩展。每个特征都可声明 `offset_bars=0..499`：`0` 是当前求值 K 线，`1` 是前一根；特征预热与偏移合计最多需要 500 根 K 线。因此“今日最低价低于昨日最低价且今日最高价高于昨日最高价”会精确比较 low/high 的 `0` 与 `1` 偏移，而不是用两日区间极值或收益率近似。系统不允许 Prompt 注入 Python/SQL/`eval` 或未注册运行时事实。规则结果为 `true`、`false` 或 `unknown`；历史不足时为 `unknown`，一律 HOLD/不买入。例如“KDJ<0 买入，KDJ>15 卖出”在默认假设下被细化为已收盘日线 J 值规则；该假设会在激活前显示，不会在运行中再解释。

这条路径仅输出研究建议或模拟交易，不连接券商。交易时段、A 股 100 股整手、T+1、现金、持仓数和总仓位等执行约束始终优先于策略动作。

已激活或已退役的冻结版本可以从“预设文字策略”回测页单独选择并历史回放。专用引擎不再次调用模型：它按冻结依赖预算获取暖机日 K，逐日执行 `selection → entry → exit`，收盘选股信号在下一交易日开盘按冻结仓位规则成交，持仓按已完成日 K 监测并执行 T+1、涨跌停、滑点和交易费用。每次任务使用独立 100 万元组合，不接触 Practice 账户；版本 ID、计划 SHA-256 和 `prompt-backtest-v1` 共同隔离任务与选股缓存。结果内嵌选股、买前复核和逐日持仓监测审计，审计清单记录各阶段数量、链指纹和确定性重放结果。回测固定执行系统静态 6 只持仓、单轮最多 2 个新仓、单票 10%、总仓 80% 和至少 20% 现金上限；生产盘面指引可能继续收紧这些值，因历史盘面指引没有完整快照，回测会明确披露而不伪造动态门槛。

## 4. 模拟决策情报包

模拟流程可以将多个来源压缩为一个结构化上下文，并随决策日志保存。默认可能包含：

- 盘面监控指引和隔夜市场摘要；
- A 股指数、A50、美股指数或期货、黄金和原油等行情；
- 板块涨跌、行业资金、成交热度与换手信息；
- 候选样本的近期消息，以及行业与市场数据的共振或背离；
- 模拟账户现金、总仓位、持仓比例、盈亏状态和规则标记。

每次实战选股会复用扫描器在当前选股范围内已经取得的实时报价，按当时的上涨/下跌家数和涨跌停广度重算盘面标签；数据覆盖率不足、快照过期或仍处于 9:25 竞价阶段时，回退到最近的竞价、午盘或盘后报告。即使本轮没有候选股，也会刷新并记录盘面上下文。

仓位比例按 `价格 × 数量 ÷ 当前模拟总权益` 计算。日志会记录单次变化占模拟总权益的比例，以及变化后的单项和总仓位比例。

相关配置：

| 配置项 | 说明 |
|---|---|
| `DASHBOARD_DECISION_INTELLIGENCE_ENABLED` | 是否启用结构化情报包 |
| `DASHBOARD_DECISION_INTELLIGENCE_TTL_SECONDS` | 聚合数据缓存时间 |
| `DASHBOARD_DECISION_INTELLIGENCE_MAX_ITEMS` | 各类信息的最大条目数 |
| `DASHBOARD_TRADE_DISCIPLINE_TEXT` | 自定义模拟纪律文本 |
| `DASHBOARD_MAX_OPEN_POSITIONS` | 最大模拟持仓数量参考 |
| `DASHBOARD_MAX_NEW_BUYS_PER_DECISION` | 单轮新增模拟样本数量参考 |
| `DASHBOARD_MAX_SINGLE_POSITION_PCT` | 单项模拟仓位比例参考 |
| `DASHBOARD_MAX_TOTAL_POSITION_PCT` | 总模拟仓位比例参考 |
| `DASHBOARD_MIN_CASH_RESERVE_PCT` | 模拟现金保留比例参考 |

百分比配置默认主要用于模型上下文和研究纪律；带注册硬限制的策略会在模拟执行层复核其自身限制。牛牛战法的单票上限由独立风险预算和 30%/25%/15%/6.25% 注册上限决定，不会被默认 10% 单票参考值压回；全局总仓、动态盘面总仓和现金保留限制仍与策略上限取更严格者执行。无论是否硬拦截，这些设置都不应被视为真实交易账户的风险保障。

## 5. 配置方式

优先在 dashboard 设置页维护当前独立策略、文字规则和模拟纪律。每轮只启用一套策略；基础策略、Z哥、李大霄、板块潮汐、牛牛战法和后续新增策略的候选、买入、卖出、仓位与 Prompt 规则互不混用。对应环境变量包括：

| 配置项 | 说明 |
|---|---|
| `DASHBOARD_ACTIVE_STRATEGY` | 当前独立策略：`base`、`zettaranc`、`li_daxiao_bottom`、`sector_tide`、`niuone` 或 `preset_text` |
| `DASHBOARD_PROMPT_STRATEGY_DB` | 冻结版本、追加式审计和持仓绑定的私有 SQLite 路径 |
| `DASHBOARD_PROMPT_REFINEMENT_MAX_CONCURRENCY` | 创建阶段 AI 细化的最大并发数，限 1～2 |
| `DASHBOARD_PRESET_STRATEGY_TEXT` | 无激活冻结版本时的旧版兼容文字，新策略应使用管理页闭环 |
| `DASHBOARD_PRESET_STRATEGY_CANDIDATE_LIMIT` | 旧版兼容候选上限；新版上限冻结在策略版本内 |
| `DASHBOARD_STOCK_UNIVERSE` | 最终候选和新买入范围，多选值为 `st`、`chi_next`、`star_market`、`main_board`；默认仅主板；牛牛的全量参考池不会扩大该交易范围 |
| `DASHBOARD_TRADE_DISCIPLINE_TEXT` | 额外模拟纪律 |

当 `preset_text` 激活且存在冻结版本时，扫描和模拟交易优先使用新闭环；旧文字只作无冻结版本时的兼容回退。升级前已有且没有新版本绑定的历史持仓不会被猜测迁移或改写。
创建阶段会在管理页实时展示模型输出，完整输出通过本地编译后才可确认激活；模型请求复用买卖决策的 `DASHBOARD_DECISION_TIMEOUT`，不维护独立的文字策略超时配置。

启用牛牛战法时，扫描器会把当前系统支持的沪深非 ST A 股全量范围（主板、创业板、科创板）作为市场与主线参考池：全量获取实时行情，并让参考池中的每只股票进入不设数量上限的 K 线深度分析，不再按成交额、当日涨幅或涨停幅度做前置过滤。最终展示候选和新买入仍严格受 `DASHBOARD_STOCK_UNIVERSE` 限制，并只要求存在可用于模拟成交的有效价格；已有持仓即使后来超出设置范围，仍允许执行止损、止盈和其他卖出风控，避免切换范围后无法退出。ST 仅在设置显式选择时才可进入最终交易范围。北交所尚未接入当前行情、板块涨跌幅和交易权限模型，因此不在参考池内。

旧版 `DASHBOARD_STRATEGY_SOURCE` 与 `DASHBOARD_ENABLED_PERSONA_STRATEGIES` 仅用于无缝读取历史配置；新设置保存后以 `DASHBOARD_ACTIVE_STRATEGY` 为准。

本地配置默认保存在 `.local-data/dashboard.env`。该文件可能同时包含模型密钥和管理凭据，不应提交到 Git 或复制到公开上下文。

## 6. 扩展独立策略

策略代码统一放在 `app/strategies/`：

- `registry.py`：策略元数据、分组、别名、启停和设置项；
- `scoring/`：指标、硬过滤、各策略评分器及多策略比较引擎；
- `selection.py`、`policy.py`：候选准入、展示筛选与仓位策略；
- `attribution.py`、`performance.py`：策略标记、归因和绩效汇总；
- `exits.py`、`prompts.py`：策略专属退出规则和模型提示词片段。

`app/screening/multi_strategy.py` 负责行情获取、全市场扫描和缓存编排，`app/trading/practice_trader.py` 负责账户、风控和模拟成交编排。旧模块名适配器集中在 `app/compat/`，新代码应从 `strategies` 包导入。

新增内置策略时：

1. 在 `app/strategies/registry.py` 增加 `label`、`color`、`desc`、`scorer`、`profile`、`position_limit_pct` 和 `aliases`；
2. 在 `app/strategies/scoring/` 的对应文件中实现 `score_xxx(rows)`，并在 `scoring/__init__.py` 的显式映射中注册；
3. 如有专属退出或决策语义，只修改 `exits.py` 或 `prompts.py`，无需把规则写回扫描器或交易器；
4. 为评分边界、空数据和异常行情补充自动化测试；
5. 运行 `./scripts/validate.sh` 完成验证。

扫描器会遍历当前启用策略的 scorer，并将 `strategy_meta` 输出给 dashboard 与模拟复盘模块。

## 7. 选股信号历史回测

`app/backtesting/` 是独立的离线研究包，不读取或修改模拟持仓、订单和成交记录。它可以运行固定持有期事件研究，也可以为已定义确定性买卖与风控规则的策略维护仅属于本次回测的独立资金、持仓和成交状态。生产扫描和模拟交易不导入该包。

文字策略使用同一套通用的 `PromptStrategyBacktestPolicy`，但每次只装载一个冻结版本；因此无需为 KDJ、MACD、RSI 等指标分别编写回测器。规则计划声明本次真正依赖的特征，版本快照、组合状态、审计链和缓存身份彼此隔离。当前历史日 K 无法忠实还原实时 K 线条件，所以专用回测明确拒绝 `bar_status=live` 的版本，而不是用日线收盘数据伪造盘中结果。

管理员设置页的每个“当前独立策略”卡片都提供独立“回测”入口。页面无需填写股票代码：后台按设置中的选股范围自动构建候选全集，牛牛战法额外使用全量沪深非 ST 股票重建主线和行业横截面，再逐日运行策略。牛牛试仓先复核 6 只强势股或连续 3 日酝酿的延续证据，每天最多保留评分最高的 2 只，并执行与模拟盘相同的早期题材阶段路由；同一股票同时匹配多个子策略时，可执行策略优先于被硬门槛阻止的高分策略，再按分数选择最优路径。牛牛回测以 100 万元独立初始资金运行：次日开盘按市场状态、止损距离和风险预算计算整手股数，执行每个交易日最多 2 个新仓、最多 5 只持仓以及单票、主题、总仓、现金储备约束；试仓和启动持仓只有满足生产阶段升级条件才允许加仓。历史回测默认把每笔可接受订单下到风险许可上限的 100%，而 Practice 使用模型明确给出的股数，并把仅超过正数风险上限的牛牛 BUY 裁到该上限；因此管理员结果会结构化返回 `entry_sizing=maximum_permitted_risk_ceiling`、`entry_order_scale=1.0` 和 `model_order_units_replayed=false`，并把组合收益、回撤标为最大定仓情景。每个买入批次独立执行 T+1，随后逐日回放结构止损、主线/龙头转弱、阶段时间退出、按入场行情与当前阶段确定的首段盈利保护、余仓成本保护和 2ATR 跟踪退出；完成卖出后可按新信号再次买入，不再使用 20 日冷却期代替真实持仓。完成后展示组合净值、最大回撤、买卖收益、子策略交易和持仓周期明细；尚未提供确定性卖出状态机的其他策略仍展示固定持有期收益。每次回测都按“暖机期＋信号期＋卖出跟踪期”从东方财富、腾讯或新浪网络接口获取日 K，不读写本地日 K 缓存。前端始终查询服务端任务，进度和结果原子落盘；刷新可恢复、运行中可终止，每个策略只保留当前一次回测。自动回测要求历史行情覆盖率至少达到 85%。

牛牛回测固定使用进取参数，不再提供均衡/进取档位选择。回测中账户风险预算放大至 1.35 倍、总仓/题材敞口预算放大至 1.15 倍，容量固定为 3/6/3；单票绝对上限、价格形态、结构止损、涨停禁买和 T+1 不放宽，也不改写 Practice 组合风控。v25 沿用 v24 的“主升动量试仓”质量条件：普通入口要求主升阶段、跨日 `emerging`、行业龙一、强度不低于 90、评分不低于 8.1、题材分不低于 70、距 EMA20 不超过 1ATR；2.5～3.2ATR 只保留单日涨幅不低于 9.5%、量比不高于 1.2 的极强加速例外。质量门通过后首仓绝对上限为 4%，结构止损仍为 18%/3ATR，次日高开仍不得超过 3%。任务与结果携带 `niuone-backtest-v25` 协议号；服务升级后旧协议或旧均衡结果不再恢复或展示。

回测 v26 与严格前向 v25 同步增加条件化“高潮余仓跟随”：必须已执行高潮减仓、个股仍强、题材分不低于 55 且未退幕/失活，才把相对龙头排名退出从连续 2 日延后到 3 日，并把余仓跟踪线从 2ATR 放宽到 3ATR。普通仓位和健康条件失效后的仓位仍执行原两日/2ATR，结构止损、成本保护、主线转弱、退幕和市场硬停止不变。任务与结果携带 `niuone-backtest-v26`，旧 v25 结果不再作为当前策略证据。

严格前向 v26 与回测 v27 允许牛牛在 `defensive` 状态开仓，但不放宽复合风险硬停止。防守档成熟路径单笔/组合/主题风险上限为 0.30%/0.90%/0.60%，总仓/主题敞口上限为 20%/12%；试仓单笔/主题风险和主题敞口进一步收紧为 0.15%/0.30%/5%。所有动作仍须通过原生命周期、龙头、形态、止损、涨停和组合容量门槛；触发 `market_hard_stop` 时继续只允许卖出或持有。任务与结果分别携带 `niuone-strict-forward-v26` 与 `niuone-backtest-v27`，旧协议证据不得混用。

严格前向 v27 与回测 v28 将事实行业和动作题材拆开：`industry/sector` 只承载东方财富 `f100` 行业，`signal_theme` 承载当前动作选择的 `f103` 概念。多概念股票不再因标签顺序或后续行业补全改变交易归属；题材归因由 75% 当前题材/个股共振证据与 25% 前序快照历史先验构成，单股全部概念的权重之和为 1。同生命周期候选优先选择归因更强的题材，原生命周期、评分、形态、结构止损和风险阈值不变。首次建仓冻结 `entry_theme`，`active_theme` 只有在替代题材连续两个交易日保持有效且领先至少 10 分时切换。前向绩效按首次入场日期×入场题材聚类，并拒绝缺失题材归因的生命周期；任务与结果分别携带 `niuone-strict-forward-v27` 与 `niuone-backtest-v28`，旧证据不得混用。

严格前向 v29 与回测 v30 将题材归因前置：`f103` 仅产生候选分支，当前证据由排除自身的同题材共振、同群方向、当日排名和结构排名形成，再与前序先验组合。题材识别不发起消息检索，消息摘要不改变候选、归因或题材总分。多概念使用 softmax 权重并保留未归因质量；题材分数、强股、成交额、结构/今日广度和领涨股按归因权重重算，今日广度另做小样本收缩，低于 15% 归因权重的股票不能成为该题材领涨股。上下文 schema v10 拒绝沿用 v9 跨日确认；任务和结果分别携带 `niuone-strict-forward-v29` 与 `niuone-backtest-v30`，不得与旧证据混用。

严格前向 v30 与回测 v31 新增 20 日市场中性化收益波形归因：个股日收益与排除自身后的题材成员中位日收益都扣除全市场中位收益，再计算逐日相关性，并按同一股票全部 `f103` 候选中的相对排名收缩。方向相同但波形无关的宽泛标签因此被降权。牛牛完整研究、分钟刷新和普通策略扫描都不调用消息检索或大模型。上下文/专用缓存 schema 升级为 v11/v9，旧证据不得混用。

严格前向 v31 与回测 v32 修复多概念股票的龙头重复稀释：15% 归因权重仍是普通题材分支的资格线，但单股归因分最高且不低于 60 的首要题材可作为唯一低份额例外；资格通过后，结构龙头按原始强度、今日龙头按当日涨幅排序，不再乘以归因权重。回测按真实次日开盘校验结构资格，5bp 模拟滑点只进入成交价与风险定仓。权重仍用于题材广度、成交额、集中度和有效样本，生命周期、买点、止损和组合风控不变。上下文/专用缓存 schema 升级为 v12/v10，旧证据不得混用。

信号回放会先对每只股票的完整历史序列做一次因果技术指标预计算，再以只读尾部视图提供给当日策略，避免逐日复制历史行或从第一根 K 线重复计算 BBI、EMA、KDJ 等指标。牛牛的四个动作还共享同一份 ATR、V 型、突破和结构风险基础量；跨日只保留下一交易日实际读取的紧凑题材状态。内置无状态策略会跳过信号开始日前不需要的评分；牛牛至少保留信号前 60 个交易日的状态回放，并且不会晚于第一个可能形成有效题材成员的交易日启动，因此只跳过尚不能产生题材状态的早期暖机日。板块潮汐仍完整回放暖机区间。

回测结果的“未入选原因”会按子策略和自然月展示股票日评分数、达到评分门槛数、通过全部条件数、主要硬性拦截条件和最接近入选的有界候选集。诊断同时给出相对生产阈值 `-1/-0.5/-0.25/0/+0.25/+0.5/+1` 的候选数敏感性、逐项硬门槛与门槛族消融可挽救数量，以及各概念/行业龙头分支的阶段和阻断覆盖。分支表明确区分“最佳标的当日阻断”与“月度累计阻断族”，月度计数不再作为单只股票某日的原因展示。消融是只读研究统计，不会自动放宽生产门槛、持仓容量或风控规则。

`historical_data.py` 默认依次从东方财富、腾讯、新浪获取日 K，带有有界超时、重试、并发和来源记录。默认使用前复权；新浪公开日线只允许在 `adjustment="none"` 时兜底。`strict=True` 会在任一股票缺失时终止，避免不完整横截面带来的偏差。

牛牛交易的组合净收益从独立初始资金出发，按每次风险定仓、阶段升级加仓和实际剩余仓位计算。进攻/修复/防守入场的试仓盘中达到 0.75R 减仓 50%，轮动入场试仓及成熟路径达到 1R 减仓 45%；整笔收益会合并所有买入、分段卖出和最终卖出，再扣除滑点、佣金、过户费和印花税。从下一交易日开始，余仓结构止损至少抬到含买入费用的平均成本。仅完整卖出的持仓周期进入平均收益和胜率，期末未卖出持仓按收盘价计入组合权益并单独显示浮动收益。次日开盘涨停、停牌、零成交量、风险预算不足一手或缺少行情会保留拒绝原因。日 K 无法还原盘中精确触发顺序：结构止损使用最低价并按止损价或跳空开盘价估算，阶段对应的 R 目标使用最高价并按目标价或跳空开盘价估算；同一根 K 同时触发时保守地先执行止损，其他完成 K 线后确认的规则仍按收盘价估算。

管理员页面从当前 A 股列表接口自动构建候选范围。历史 K 线优先使用东方财富，其次腾讯；仅不复权模式再以新浪作第三数据源。牛牛按东方财富 `f103` 概念多标签聚类，板块潮汐按同源 `f100` 行业聚类，不读取申万或同花顺分类。牛牛试仓只使用各交易日收盘前已经取得的日 K 数据，并与其他牛牛子策略一起参与历史回放。

## 8. 使用边界

- 不要将模型生成内容视为事实，应回查原始数据和信息来源。
- 不要使用本项目替代持牌机构服务、专业风险评估或个人独立判断。
- 历史回放、规则评分和模拟结果不代表未来表现。
- 扩展数据源时，应确认数据授权、调用频率、隐私和再分发要求。
